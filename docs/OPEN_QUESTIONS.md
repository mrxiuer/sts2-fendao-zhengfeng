# 待决事项与验证清单

以下项目不覆盖已确认规则，不以默认实现暗中作出产品决定。

## 玩法边界

- 献祭路线锁定与预览：玩家能否先看多个池再选路线；无论如何不得重抽候选。
- 已领取后的同场奖励顺序，以及限时增益在 Boss 击杀、献祭和额外奖励间的到期边界。需要保证新取得增益不会因同一次击杀立即失效。
- 当前双刃不重复持有，与早期先苦后甜、过河拆桥、贪婪口袋的强化草案如何归并。前两轮已有的强化讨论不自动视为最终可触发规则。
- 候选不足且无法满足 Boss 保证位时，如何回退或保留遗物；不允许先吞奖励再发现无候选。
- 先苦后甜的 X 费、无法重放的第三张、目标消失和重放联动。
- 硬壳与即死、敌方变身、多血条、召唤及血肉滋长的先后关系。
- 盛放与凋零中复制、变化、升级、删除对原卡身份和耐久的继承，枯萎牌删除与恢复的显示。
- 过河拆桥的跨角色兼容名单，基础牌与升级次数的合法映射。
- 净化待生效攻击的合并显示和费用；已激活与待生效同名部分的原子清理时机。
- 金币复制与治疗等整数舍入顺序；时间窗内断线玩家收入的归属。
- 同刻 Boss 击杀与通关的正式排序、网络延迟处理、暂停与动画速度规则。
- 全员淘汰、断线超时、房主退出及未完成者的最终名次与观战权限。
- 工作名称的最终命名及英文、本地化范围；作者署名、发布许可证与工坊页面文案。

## 技术验证

- 本地 v0.111.0 的加载清单与运行时接口，目标支持分支和依赖版本。
- 多个独立房间、战斗和幕能否在单局环境隔离；原生存档是否能扩展为个人进度。
- 个人战斗验证策略、原生消息路由的修改范围和房主迁移可行性。
- MOD 生命周期撤销、游戏更新适配、版本握手和旧存档升级策略。
- 工坊条目元数据格式、上传器版本与独立订阅环境加载。

## 平衡验证

诅咒数值、献祭三路线取舍、双人至多人群体攻击收益、重复增益成长、首杀优势、商店净化价格、Boss 档清除窗口和负担补偿曲线都尚未经实测。目标是完整模式的可玩性，不以可加载成功替代玩法验证。
