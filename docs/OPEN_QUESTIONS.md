# 剩余决策与验证

完整设计范围保持不变。以下区分代码当前采用的规则、仍需产品确认的边界，以及待完成的实机验证。

## 本构建采用的处理

- 献祭可以返回并查看另一条路线，但同一奖励、同一路线的候选固定，不能重抽；提交后其他路线失效。
- Boss 保证位无法满足时拒绝该路线并保留遗物，不吞掉奖励。当前同名双刃不重复持有，净化后按历史降权重新进入候选。
- 首杀和通关顺序按房主确认顺序。新取得的限时增益不会被刚击杀的同一 Boss 立即清除。
- 净化合并清除同名已激活及待生效攻击，费用按合并后的层数计算。商店仍不能净化 Boss 档。
- 硬壳按开战时生命上限计算，先计入血肉滋长，不随战斗途中上限变化重新扩大额度；即死命令不作为普通扣血处理。召唤怪不继承开场敌人效果。
- 先苦后甜只统计手动出牌，自动出牌不会额外触发第三张重放。X 费仍使用原生消耗全部能量规则，费用翻倍对其不生效；这一边界需要用户确认。
- 过河拆桥保留原牌合法升级次数；不兼容的星数牌排除在生成池外。盛放耐久归属于永久原卡，枯萎时保存原生卡牌包，用于营地恢复。
- 原始状态塞牌以原生 creator 信息区分来源；第三方 MOD 如不提供正确来源，转发归属可能受影响。

## 仍需确认的玩法边界

- 是否限制候选跨路线预览，以及近同时通关是否需要额外的延迟补偿裁定。
- X 费的最终惩罚方式、无法重放的第三张卡牌和敌人目标消失后的体验。
- 多血条、敌人变身、吞噬和特殊即死与硬壳、替死鬼的精确定义。
- 新增卡牌、复制、变化和升级在全部角色机制下的耐久继承；跨角色生成兼容名单是否进一步收紧。
- 未完成者的最终名次、淘汰后战斗观战及房主提前离场策略。目前只有公开比赛进度面板，没有远程战斗画面观战。
- 工作名称、英文、本地化、作者署名、发布许可证与工坊文案。

## 后续技术与平衡验证

- Steam 真实多机、三至四人、跨幕错位推进与全幕通关。
- 断线后的体验与共同检查点回退。目前没有热重连和房主迁移。
- 全部角色、特殊卡牌、敌人阶段转换、原版保命来源的组合回归。
- 原生奖励、营地和商店的鼠标/手柄操作及不同分辨率表现。
- 独立工坊订阅环境、关闭 MOD 后的原版回归、游戏版本升级与旧存档升级策略。
- 群体攻击强度、重复成长、首杀优势、净化费用与负担补偿需要完整对局数据；自动测试通过不代表平衡已完成。
