# 原生领取确认与个人备份交接

## 重现与修复

原生奖励已经发放、claim已经由房主确认，但客户端尚未执行后置Checkpoint便断线时，房主可能仍持有领取前的原生钱包和奖励列表。共享Match却已消费奖励，导致恢复时丢失已领取物品。`RewardRecovery -ConfirmedClaim` 在原实现上真实重现：断线后的房主归档断言失败。原始失败日志保留于 `artifacts/verification/native-claim-before-fix-20261023`。

普通原生领取现在先通过原有可靠、有序通道发送已发放快照，再发送 `native_claim`。房主在快照已通过原生包验证、包含完全一致的原命令完成凭证后，才执行首次领取；已经处理的原ID仍幂等接受。房主本机领取也先接收本机备份再确认。快照缺失、无效或对应命令不一致时，不确认领取，不消费该奖励。暂存记录的自动重试使用同一备份优先路径，不绕过检查。

本改动不增加磁盘落盘点；新增的是确认前的原生恢复备份传输。领取后的个人检查点仍保留，避免与其间其他本地变化混用旧原生包。实际时延需按四进程专项验收，不凭“增加一次备份”推断无影响。网络握手更新为 `wire:3`，所有联机玩家使用相同新构建；完整归档格式保持可读。

奖励钩子中再发放原生奖励时，内层完成记录先暂存，不等待仍在执行的外层生成快照；外层完成后再提交和补齐内层。否则内层等快照、外层等内层返回会形成死锁。此处只延迟权威记账，不再次发放原生物品。
