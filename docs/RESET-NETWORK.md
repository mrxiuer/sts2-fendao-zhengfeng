# R键四人恢复验收

2026-10-22执行：`scripts/Verify-Native.ps1 -Suite ResetNetwork`，以及独立归档的 `-Suite ResetNetwork -ResetEmptyMap`。两项均已通过四个真实ENet进程的新局与全进程重启，不使用Steam好友连接。

## 流程与证据

玩家1、3通过实际offer/choose取得R键和七个新效果；玩家2、4作对照。玩家2先实际击杀原第一幕Boss，形成真实首杀记录。两名持有者随后各自使用R键、从第一幕重新出发，杀Boss后仍取得自己的远征首杀奖励，但不会改写玩家2的原首杀记录。

持有者使用4100/4300生命是测试夹具，为了满足巨人化对真实Boss的斩杀条件，不是正常平衡。通过原生1点攻击验证20%强化后的Boss实际死亡，再显式调用原生胜利检测；直接执行AttackCommand不等于正常CardPlay，不自动调用该检测，这属于夹具修正，未因此修改巨人化机制。

重置前后逐项核对牌组、遗物使用状态、生命、金币、傀儡生命、遁地进度和已消耗的刷新机会；共享第一幕地图内容一致，不重复发放尾巴。玩家2保留已领取金币后的Boss奖励，玩家4保留真实购买/删牌后的商店状态。两人原房间和进度不受其他玩家重置影响。

持有者实际进入下一幕并再次战斗，验证没有使用已销毁的Boss地图节点。保存时保留双生独立生命和遁地状态；全部退出后由房主归档恢复，逐项核对次数、首杀奖励、资源、状态和对照玩家进度；未完成战斗的遁地使用仅退回一次，后续胜利不重复结算。

正常场景通过下一幕实际地图节点进入战斗；EmptyMap场景使用调试入口在新幕尚无VisitedMapCoords时进入战斗，归档目录分别为 `ResetNetwork-suite` 与 `ResetNetwork-EmptyMap-suite`，日志见 `artifacts/verification/network/*-ResetNetwork*.log`。

## 修复与范围

原生加载在无已走节点时忽略明确的房间快照，恢复成地图。现在仅对已进房的显式快照恢复该房间，并先写入原生CombatReplayWriter初始状态，保持回放与回合检查正常。不能跳过回放初始化直接开战。

本专项不替代R键操作尚在进行时保存、第五幕心脏全部组合、事件私有状态和后期联机性能验收。七项新效果仍未开放正常候选池。
