# 后期联机金币奖励性能验收

2026-10-22，本机四个真实ENet游戏进程，Ironclad/Silent/Defect/Necrobinder；每人160张原生永久牌、12个模式效果。夹具注入120条胜利历史及3000条已处理命令，构建约211KB比赛状态；不是声称已经人工打过120场。

每人实际进入12次普通战斗、调用原生击杀并等待奖励屏幕。屏障让四人同时通过NRewardButton.OnRelease领取真实GoldReward；计时直到按钮任务及权威领取记录完成，包括10ms观察轮询，不只测JSON或直接调用规则。每次再次选择均被拒绝，金币不会重复领取。每个路径48次点击，其中客户端36次。

## 修复

- 网络更新由50ms界面计时器移到逐帧ProcessFrame；较重的HUD、队友信息等仍以原频率刷新，不把全部UI工作搬到每帧。
- GoldReward选择期间，用异步上下文局部的收入收集器，合并正常金币收入统计与claim。Core同一原子事务提交领取标识和有福同享收入，避免两次串行确认。普通事件、商店、遗物及模式金币仍走原收入规则；失败或取消但已产生原生收入时仍单独记录，不丢账。
- 双击/旧领取记录/非法金币参数不能重复增加收入或消耗奖励；新增核心检查通过。原生金币金额和贪婪口袋加成顺序保持原行为，收入统计继续使用加成前的正常收入。
- 独立保存lastCompletedClick，避免房主处理其他玩家命令时覆盖本次点击的阶段报告。

最初夹具已完成48次点击，但房主发送最后一个屏障释放后立即退出，使客户端超时。夹具在最终释放后等待500ms给ENet发送；之后同一构建的基线和优化两轮均完整通过，不把首次退出失败记为套件通过。

## 尚未验收

这是一阶段的金币按钮路径，不代表卡牌选择、遗物献祭、多选一/刷新等所有奖励都已完成性能验收，也不代表互联网Steam连接或实际图形帧率。各类奖励需继续同场景采样，优化后的经济、网络、奖励存档回归和最终All仍需核对。不得以本报告提前发布完整版本。
