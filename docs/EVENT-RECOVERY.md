# 事件保存与恢复专项

2026-10-22，本地开发版0.5.0，尚未发布。以下是已实测的事件边界，不能视为全部事件页面均已支持。

## 两种真实进程场景

运行 `scripts/Verify-Native.ps1 -Suite EventRecovery`：房主通过原生破旧人偶事件选择第二档并进入战斗，保存时战斗未结束；客户端完成同一事件战斗，已自动返回最终页面并领取两张升级。客户端掉线后由房主归档，双方进程退出后从房主归档恢复。

运行 `scripts/Verify-Native.ps1 -Suite EventRecovery -EventGold`：房主仍停在未完成的人偶战斗；客户端通过原生DenseVegetation事件实际扣8生命、领取随机金币，并停在完成后的页面。此场景单独使用 `EventRecovery-Gold-suite` 归档与 `*-EventRecovery-Gold*.log`，不覆盖人偶场景。两种场景均可加 `-ResumeOnly` 复用同一落盘归档。

两种场景均已通过新局与全部进程重启；之后追加完整事件随机状态与新节点收益检查，并对同一归档重启实测通过。

## 已通过

- 未完成的人偶战斗恢复真实父事件与战斗两层房间栈；从第1回合开始，保留战斗编号、身份、生命、最大生命、金币与永久卡包。胜利后原生自动返回人偶事件，仅升级两张牌，胜利只结算一次。
- 已完成的人偶事件恢复原最终页面与空选项，不重新进入初始三选一，不重新升级。
- 已完成的DenseVegetation恢复原最终页面，保留已扣生命与已领金币；不重新生成初始选项、不再次扣血或发金币。
- 完成页面的房间身份、实际显示文本与完整事件RNG原生包逐项等于房主归档。
- 再次继续不会重复升级、金币或生命变化；之后真实进入新战斗，得到新的战斗身份。
- 两名玩家都持有原生MawBank：恢复父事件和完成页面时不重复得到进房金币；恢复完进入后续新房间仍正常得到一次12金币。

原生人偶遭遇不提供普通战后奖励列表，会自动返回事件；专项按真实路径等待与检查，不人为制造奖励列表。前置战斗通过实际地图节点进入，人偶及植被事件通过原生EnterRoomDebug指定，选择走原生EventSynchronizer，战斗胜利用原生击杀调试功能；不替代实际分路选点或完整打牌验收。

## 修复

原生加载只为IsPreFinished的事件战斗重建父房间，未完成的事件战斗会失去父事件。现在仅在明确的已进房存档加载期间，为未结束战斗补齐父事件与子战斗，父事件重建阶段不重复推进模式进度或保存中间假房间。

EventRoom.ToSerializable没有普通事件的最终页面。现在保存已完成Default布局事件的最终文本、事件RNG和房间身份；重建时直接恢复完成状态，不运行初始生成或启动收益钩子，也不对新模型重复执行旧模型的结束清理。Ancient和Custom等其他布局不由此通用完成页路径接管。

自定义房间快照包含进房后的资源，原生存档则通常保存在进房前。恢复明确的房间快照时不再重复BeforeRoomEntered/AfterRoomEntered收益，仅恢复本模式的追踪与待落实收据；也不把恢复当作又走了一个节点结算模式收入。没有显式房间的旧共同检查点仍按进房前处理，不能用统一禁用所有读档进房效果替代。

本轮最终回归实际通过：EventRecovery与EventRecovery-Gold的保存/重启及完整RNG比对，ServiceRecovery、FourPlayers、Recovery、RewardRecovery各自全新局与重启，以及Network和旧共同检查点Resume。构建0警告/错误、81项核心检查通过。验证仅启动和结束脚本自己创建的进程；已退出进程不再被误判为用户仍在运行游戏。


## 未结束的植被页面

新增 `-Suite EventRecovery -EventPage Initial` 与 `-Suite EventRecovery -EventPage Rest`，分别使用独立归档 `EventRecovery-Initial-suite` 和 `EventRecovery-Rest-suite`。两项均已通过真实双进程新局、客户端断线后房主保存、全部退出重启。已加入All入口，可单独加ResumeOnly复用归档。

初始页：保存原页面、选项、Gold/Heal/HpLoss动态值和完整事件随机状态，恢复不重新运行CalculateVars。实际选择TrudgeOn后，精确支付保存的8生命并领取保存的金币数值一次。

休息后页面：实际先执行原生Rest获得治疗，再保存只有Fight选项的未完成页面。读档不重新治疗，不退回初始页。恢复的Fight实际进入原生遭遇并胜利，模式只记录一次胜利，之后可以继续新的战斗。

实现显式植被页适配，不序列化运行中的Task或反射复制旧委托。恢复时重新绑定本次EventModel的原生选项回调；使用已保存的RNG和动态值，跳过启动收益钩子；开放页面仍按原生结束清理。其他事件的私有状态、其他多页事件和选择执行中的存档仍需后续适配，不以两个页面通过代表通用事件已完成。
