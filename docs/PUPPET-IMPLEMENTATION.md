# 替身傀儡实现与验收

## 已确定的完整规则

- 取得时获得真实跟班，初始最大生命等于取得时玩家最大生命；自带原生壁垒。
- 玩家的格挡转给傀儡，攻击与负面效果优先由傀儡承受；角色无法正常治疗。
- 用户确认：攻击打死傀儡后的溢出伤害由角色承受。傀儡死亡移除道具，恢复角色正常受击与治疗。
- 用户确认：傀儡承受战斗内施加给角色的负面状态；状态牌照常进入玩家牌堆，模式诅咒记录保留。
- 跨战斗保留傀儡剩余生命，战斗结束清空格挡；战斗内壁垒按原生规则保留格挡。
- 重复取得增加初始最大生命的25%上限，并恢复同等生命；按初始值线性增长，不逐次乘算。
- 角色原生复活仍正常生效。实际生命恢复、生命支付、最大生命变化需分别验证。

## 当前已实现的基础

`SubstitutePuppet` 是真实原生宠物，拥有独立的生命、格挡和状态，不使用角色血量或格挡数字作为替身。独立透明立绘、遗物图标、轻微待机动作、原生血条与状态栏已经接入。

原生 `CreatureCmd.Damage` 通常让宠物消耗主人的格挡。`PuppetDamageScope` 只在涉及傀儡的伤害中替换这一查找，使它消耗自己的格挡；按当前受击对象更新上下文，避免同一次群体伤害混用角色与傀儡格挡。嵌套伤害另建上下文并在结束或异常时恢复。

原生宠物布局会隐藏整个状态栏。傀儡单独保持可交互的血条与状态显示，死亡和调试隐藏仍走原生流程。实际图形验证发现默认宠物站位会与角色血条重叠，已将傀儡放到角色前方，独立显示身体、血条与状态。

测试专用的 `GuardsOwner` 开关已接入真实攻击转移：使用原生伤害重定向和溢出路径，先消耗傀儡自己的格挡和生命，超出部分由角色承受。傀儡易伤影响它实际承受的攻击，伤害预览采用同一目标；受击前钩子、格挡历史、破盾事件和特效归属傀儡。死亡后的后续命中回到角色，不再产生第二次伤害命令。普通非攻击生命损失不按攻击转移。

这仍是隔离测试开关，不是完整道具。取得、存档、格挡生成转移、状态转移和治疗限制尚未接上。

专用基础验证：`scripts/Verify-Native.ps1 -Suite PuppetBody`。图形验证：`scripts/Capture-Native.ps1 -PuppetBody -OutputDirectory <绝对目录>`。验证实际宠物身份、独立生命/格挡、壁垒跨回合保留、原生中毒/易伤/脆弱/负力量、独立血条与状态、待机动作、敌人默认选敌不重复包含宠物、死亡与重新创建。

原生无界面与实际图形测试均通过28项检查；构建零警告、零错误，核心规则72项检查通过。单进程基础与关闭模式的原版双进程联机回归通过。

**目前没有加入 Catalog、配置或任何奖励池。上述验证只证明真实跟班基础，不能当作完整道具已完成。**
