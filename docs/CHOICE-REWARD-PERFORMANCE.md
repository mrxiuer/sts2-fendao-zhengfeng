# 后期卡牌与模式奖励性能调查

当前为调查和修复记录，献祭尾部延迟门槛尚未通过，不代表完整性能验收结束。

## 场景

复用四职业真实ENet大状态夹具：每人160张永久牌、12个模式效果，120条胜利历史、3000条已处理命令。每人进行8场真实原生战斗，通过原生奖励按钮分别测两次卡牌、遗物领取、遗物献祭和Boss额外护盾；每路径32份选择记录，客户端各类型6份。

卡牌分别记录界面可见OpenMs、原生可点击ReadyMs，以及GUI选择后到原生取得和权威凭证完成的CommitMs。等待原版NCardHolder的_isClickable解除后通过_GuiInput触发真实选牌，不直接调用私有SelectCard绕过保护。0.35秒防误点参数保留，实际就绪时间单独记录，不混入网络结算。

遗物领取固定使用Vajra/Anchor避免随机遗物本身改造牌组；献祭使用实际精英遗物和混合池，选择无额外选牌前置交互的增益或干扰。Boss护盾使用夹具预先配置的两份奖券，但选择、领取、护盾变化与去重均走原生奖励和实际Core命令。不会声称是四人正常竞赛自然取得全部前提。

所有动作在点击前通过屏障对齐；人的思考和等待其他玩家的屏障时间不计入CommitMs。献祭从两选一到混合候选的IntermediateMs另计。旧奖励再次选择必须立即返回false且不再弹窗。

## 已修复与继续定位

已消费的遗物原先会先弹领取/献祭菜单，再检查领取凭证。现将凭证检查移到所有选择之前；卡牌、遗物、献祭与Boss奖励的重复选择专项均实际返回false且不重开对话框。原生Reroll和RewardRecovery新局/重启回归通过。

夹具修正：换房须等待RaceRuntime.RewardRoom等于当前房间，避免误读上一场未关闭奖励；重复选择检查前等待原生延迟销毁的旧对话框退场，不能把旧UI尚未Free当作重开。

献祭长等待主要在Submit，不在本机Core克隆或快照（后者毫秒级）。继续细分命令信号量排队和网络往返；嵌套UiOptionReward不是新领取，性能跟踪保持外层领取，避免覆盖待确认交互的state_apply计时。此定位不改变命令排序或存档语义。
