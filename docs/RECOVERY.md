# 房主保存与继续比赛（本地开发版）

本轮未发布。已通过双进程 ENet 的断线保存、未结束战斗恢复及已结束战斗的精确剩余奖励恢复测试；事件、淘汰与全部新增效果的完整存档验证仍未完成。

## 使用方式

房主从暂停菜单点击“保存并退出”。不要求其他玩家完成房间或到达下一个节点，已经掉线的玩家使用房主收到的最近一次备份。存档成功后退出；失败时仍保留在比赛中并显示原因，不覆盖之前可用的存档。

重新启动后，房主在主菜单点击“继续分道争锋”，邀请原来的玩家，双方选择原来的角色后开始。客户端从房主取得自己的恢复包，不要求客户端本机存在共同检查点文件。主菜单原有单人继续按钮仍使用原版存档。

未结束的战斗重建相同遭遇并从第1回合开始，保留保存时的永久牌组、生命、金币、药水、遗物及模式状态。已消耗物品不返还。开场属性重新施加，开场的直接扣血不会再扣；已进入战斗后收到的诅咒仍在下一场激活。

战斗已经结束、停留在奖励界面时，保存具体剩余卡牌候选、升级数值、遗物、药水、金币和模式额外选项。恢复时展示原来的内容，不重新生成；已经领取的奖励不再出现。原生教程固定候选和普通随机候选分别保留原来的行为，普通候选仍响应新取得的蛋类遗物。

“多人模式”仍可新开比赛，不会因为存在恢复存档就自动恢复。旧的调试共同检查点保留为单独来源，不会误读新的房主归档。

## 数据与时序

- 原版运行状态继续使用 `ShouldSave=false`，不覆盖原生单人存档。
- 日常比赛状态和个人检查点通过后台队列原子写入，同一文件有多次更新时合并为最新内容；离开比赛前等待队列完成。只有不可变文本传入后台，原生状态捕获仍在游戏线程完成。房主明确保存退出的归档仍需等待写入成功才退出。
- 房主归档写入 `user://FendaoZhengfeng/recovery/<房主ID>.json`，采用临时文件加原子替换。
- 每个独立战局定期向房主发送原生 `SerializableRun`。保存时冻结操作并请求在线客户端补发，掉线者使用最近备份。掉线前尚未送达房主的本地操作可能回退至备份。
- 房主额外保留待落实的资源收据。原生快照未包含的已确认金币仍可恢复，快照已包含的收据则不再执行。
- 卡牌交易的两个交接标记分别与对应原生快照对齐，避免仅凭共享状态的完成标记漏交牌。
- 重建战斗时保持原来的个人战斗编号，不额外推进诅咒激活边界，不再次消费开场服务。
- 存档和恢复要求相同规则版本、玩家名单与角色。目前没有房主迁移或运行中的热重连。

## 验证

运行 `scripts/Verify-Native.ps1 -Suite Recovery`，使用独立内存进度与 `artifacts/verification/recovery-suite` 测试归档，先启动两进程创建断线场景，再重启两进程恢复。

已覆盖：实际暂停菜单保存调用、断线后房主独立落盘、主菜单继续入口、客户端没有个人恢复文件、战斗回到第1回合、生命与最大生命、开场力量、扣血不重复、未来诅咒不提前激活、已确认但未进入原生备份的金币补发与确认。狂赌之心的战斗内判定计数会随本场重开清零；真实双进程已比较掉线前与重开后的前三次实际攻击，验证暴击序列从本场起点重放。

运行 `scripts/Verify-Native.ps1 -Suite RewardRecovery` 使用 `artifacts/verification/RewardRecovery-suite` 隔离归档。覆盖客户端在奖励界面掉线、房主单独保存、重启双方后逐项比较原始奖励、已领金币不重复、二次强化候选与选择限制、关联奖励结构、原生遗物更新普通候选、模式选项实际领取、防止重复领取及恢复后新增奖励标识不冲突。

尚需覆盖：营地和商店内保存、嵌套事件战斗、四人在线共同保存、已淘汰玩家、R键后恢复及所有新增效果。还需处理在奖励生成或领取尚未完成时保存，以及掉线前共享命令已确认、对应原生快照尚未送达的跨阶段对齐。不能将稳定奖励界面的通过结果当作所有中间时序均已解决。

旧版没有生成房主归档的历史对局，不能仅凭这个入口恢复所有人的完整独立进度。
