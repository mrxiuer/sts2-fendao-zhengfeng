# 奖励领取性能记录（本地开发版）

本轮尚未发布，也尚未证明所有奖励卡顿均已消除。

## 已修改

- 房主提交命令后只序列化一次比赛状态，同一份文本用于个人落盘和网络广播；客户端直接复用收到的状态文本。
- 日常写盘使用后台合并队列。慢磁盘期间，同一文件只保留最新待写版本；退出比赛前等待写入完成。写入失败会显示错误，后续新快照可以重试。
- 一次检查点只生成一个原生快照，供房主恢复备份和个人检查点共用。后台仅接收文本，不操作 Godot 或游戏模型。
- 未打开的调试面板不再反复重建，效果栏结构不变时只更新内容。

## 验证

70项核心检查中包含慢磁盘阻塞时合并1000次更新、退出刷盘、写入失败后重试、真实文件原子替换与临时文件清理。

真实双进程 `Network` 检查验证了 `checkpoint.json` 的最新共享修订号、当前战斗标识、可读取的原生进度和已应用收据列表。一次检查点捕获与入队实测：房主0.70毫秒，客户端0.65毫秒，磁盘完成另外等待并核对。这是隔离测试的一次采样，不是奖励点击总耗时，也不是复杂长局的性能保证。原始记录在 `artifacts/verification/network/host.log` 和 `client.log`。

`Recovery` 的断线归档及重启恢复、`Resume` 的共同检查点恢复也已通过。

## 尚需核对

完整奖励点击耗时需要区分原生动画、界面更新、命令的全状态复制、压缩与网络往返。后续应使用包含多种效果和较大牌组的真实奖励场景测量，不能单凭后台写盘优化宣布整体卡顿已解决。
